# nooboard SSH 工作区详细方案

状态：第一版实现基线；独立 SSH crate 已开始实现，core 与桌面接入待完成。日期：2026 年 10 月 10 日。当前代码能力与验证范围见 [SSH crate 文档](../crates/ssh/README.md)。

SSH 工作区面向已配对、网络可达的设备，提供密码登录、交互终端和 SFTP 文件浏览及传输。顶部管理设备与会话，右侧显示远端文件树。文件树独立管理浏览路径，通过输入路径和选中终端输出中的路径定位，不依赖远端 shell 类型。

本方案固定产品行为、模块职责和验收条件。具体 Rust SSH/SFTP 库须通过最小验证后选择；不得为了适应某个库而取消分批列目录、主机密钥验证或连接生命周期隔离。

## 已固定的产品决定

| 项目 | 第一版行为 |
| --- | --- |
| 设备入口 | 从已配对设备中选择，以稳定设备 ID 关联连接配置 |
| 网络范围 | 同一局域网或已有 VPN 等可直接连通环境；沿用设备地址发现，不新增公网中继或 NAT 穿透 |
| 登录 | 用户名、密码、SSH 端口；默认端口 22 |
| 记住密码 | 默认不勾选；勾选且认证成功后，保存到操作系统凭据库 |
| 连接失败 | 回到登录表单，清空密码及记住密码勾选；保留设备、用户名、端口和具体错误 |
| 终端与文件服务 | 使用彼此独立的 SSH 连接，文件连接承载 SFTP |
| 文件传输 | 上传、下载统一使用 SFTP，由 nooboard Rust 后端管理 |
| 文件树位置 | 右侧可折叠、可调整宽度的面板 |
| 文件树根路径 | 来自 SFTP 初始目录、用户输入或用户选中的路径 |
| shell 集成 | 不注入钩子，不修改 shell 配置，不探测 shell 进程，不解析用户命令来推断目录 |
| 目录同步 | 不提供自动跟随或自动查询终端 pwd 的功能 |
| 目录读取 | 验证路径不列举子项；首次展开时读取下一层，大目录分批继续读取 |
| 上传入口 | 原生文件选择器及拖入远端目录节点或根目录空白区 |
| 下载入口 | 选中文件后下载到已设置的本地目录 |
| 下载目录 | SSH 工作区独立设置一个持久化目录，所有 SSH 会话共用；与普通接收目录分开 |
| 传输生命周期 | 切页、关闭终端或终端连接断开不取消独立文件连接上的任务 |

访问权限由远端 SSH 服务、认证账号及远端文件系统决定。对方需要已经启用 SSH；文件功能还需要该 SSH 服务提供 SFTP。本版不新增 nooboard 的逐次远程申请、允许本次或按设备撤销 SSH 授权流程，也不代替对方修改系统 SSH 配置。

## 页面布局与交互

```text
┌─────────────────────────────────────────────────────────────────────┐
│ 会话标签 A   会话标签 B   ＋ 新会话                                    │
│ 设备选择   用户名与地址   终端状态   文件连接状态   重连   文件面板开关   │
├───────────────────────────────────────┬─────────────────────────────┤
│                                       │ 远端路径 [             ] 前往│
│                                       │ 上级   初始目录   刷新       │
│              SSH 终端                 │                             │
│                                       │       懒加载文件树           │
│                                       │                             │
│                                       │ 上传   下载                 │
│                                       │ 下载至 [本地目录] 更改       │
├───────────────────────────────────────┴─────────────────────────────┤
│ 传输任务入口与可展开队列：方向、文件、设备、进度、目标位置、状态、操作   │
└─────────────────────────────────────────────────────────────────────┘
```

不增加左侧设备栏。顶部设备选择用于新建会话；已有会话绑定设备，切换设备创建或切换另一个会话，不改变现有任务的目标。允许同一设备打开多个独立终端，每个工作区拥有自己的浏览路径和文件连接。

右侧面板收起时终端获得更多空间。窄窗口使用可覆盖终端的右侧抽屉；打开抽屉不自动读取目录。传输队列可以在关闭所属终端标签后继续查看，并保留设备、方向、源路径和目标路径。

终端组件默认采用 xterm.js，封装为只处理终端数据、输入、尺寸和选择的适配组件。它不决定连接状态、登录结果、任务结果或文件树路径。远端输出作为终端数据处理，不注入页面 HTML；扩展控制序列不直接触发本地文件操作或应用命令。终端输出的信任边界参照 [xterm.js 安全说明](https://xtermjs.org/docs/guides/security/)。

## 设备连接与凭据

### 地址解析

连接配置关联稳定的 `noob_id`、用户名和 SSH 端口。每次新连接从设备模块获取最新地址候选；本次连接选定的地址单独记录。nooboard 发现端口、配对端口与 SSH 端口是不同配置，不互相替代。

IP 改变时，下一次连接重新解析地址。不会把已建立的 SSH 连接无缝迁移到新 IP。nooboard 的设备在线状态和 SSH 服务可达状态分别展示，设备在线不代表 SSH 已启用，设备发现离线也不作为已建立 SSH 会话的强制断开依据。

### 身份验证

第一版只提供 SSH 密码认证，不配置用户私钥、ssh-agent 或多因素交互认证。服务器不提供密码认证时明确提示原因，不尝试改变服务器设置。

nooboard 配对证书与 SSH 服务器主机密钥是两套身份材料。首次遇到 SSH 主机密钥时显示算法及指纹，由用户核验并确认后保存；已记录密钥发生不匹配时停止连接，不继续发送密码。更新主机信任是独立的显式操作，重新输入密码不能绕过该检查。此行为遵循 [OpenSSH 主机密钥检查的基本原则](https://man.openbsd.org/ssh_config#StrictHostKeyChecking)。

公开的主机信任记录由 core 持久化，关联稳定设备和 SSH 服务配置，不只按可能变化的 IP 保存。地址发现仅提供连接线索，不自动批准 SSH 主机密钥。两条独立 SSH 连接都验证主机密钥。

### 密码保存规则

首次表单包含设备、用户名、端口、密码及未勾选的“记住密码”。已保存有效凭据时提供一键连接，不把密码回填到前端。

用户提交的一次密码输入可以用于本次终端连接和文件连接的认证。即使不勾选记住密码，也可以短暂保留在后端内存中完成这两次认证；本次连接尝试结束后释放。已有连接继续工作不需要再次输入密码，但未来重新认证需要重新输入或读取已保存凭据。

只有用户明确勾选且认证成功，才保存密码。凭据保存失败不撤销已成功的连接，但必须提示“连接成功，密码未保存”，不能显示为已经记住。持久化密码位于系统凭据库，配置、快照、事件、Debug 和日志均不得包含密码。

连接或重新认证失败后，相应入口返回登录表单，密码为空、勾选清除。该连接配置的已保存凭据立即失去一键使用资格，并尝试删除；删除失败也不能继续自动使用。用户名和端口保留，错误原因照实显示，不把超时或网络错误统称为密码错误。这是产品层的一致性规则。

用户主动关闭终端、正常退出 shell、路径不存在、无权列目录、单个传输失败或 SFTP 子系统不支持，不视为密码失败。终端认证成功但 SFTP 不可用时，终端仍然可用；文件面板显示自己的错误。

### 持久化范围

| 数据 | 保存位置与作用域 |
| --- | --- |
| 连接配置 ID、设备 ID、用户名、SSH 端口 | core 的非秘密配置，按连接配置保存 |
| SSH 主机公开密钥、算法及指纹 | core 的公开信任记录，绑定设备和 SSH 服务 |
| 密码 | SSH 凭据适配管理的系统凭据库；core 只保存引用和是否允许一键使用 |
| SSH 下载目录 | core 的 SSH 全局设置，与普通接收目录分别迁移和更新 |
| 有效浏览路径、目录缓存、连接代次 | 当前进程内的工作区状态，不作为下次启动自动恢复的承诺 |
| 输入框草稿、节点展开及选择 | 前端呈现状态，不持久化密码草稿 |

配置扩展沿用现有文档版本及迁移机制，保留原有设备、接收目录和其他设置。未知版本或迁移失败明确报错，不重置原配置。主机信任写入成功后才继续首次认证；凭据库故障不能降级为把密码写入普通配置。

## 文件树路径与验证

### 初始路径与输入规则

文件连接建立后，通过 SFTP 解析其初始目录并验证目录属性，显示一个收起的根节点。此路径称为“初始目录”，不称为终端当前目录或保证等于系统用户家目录。

文件树每个工作区独立保存 `browse_root`。新工作区从初始目录开始；同一工作区切换标签后保留自己的路径和有效缓存。输入栏草稿与已经生效的根路径分开保存。

| 输入 | 解释 |
| --- | --- |
| 绝对路径 | 交由当前远端 SFTP 服务解析 |
| 相对路径 | 相对于提交时的文件树根路径，不相对于终端 pwd 或当前高亮条目 |
| `.` 和 `..` | 基于文件树路径，通过远端路径规则解析 |
| `~`、`$HOME`、`%USERPROFILE%` | 第一版不进行 shell 展开；提供“初始目录”按钮作为直接入口 |
| 含空格或 Unicode 的路径 | 作为路径数据传递，不要求 shell 引号转义 |

远端路径使用独立 `RemotePath` 类型，不拿本机 `PathBuf` 规则解释远端路径。Windows 的盘符、分隔符及 SFTP 路径命名空间由远端路径适配处理，并以服务端解析结果为准；这属于文件协议适配，不属于 shell 适配。

### 提交与验证

只有按 Enter 或点击“前往”才查询，输入过程中不逐字符发请求。

1. 固定本次输入、会话 ID、文件连接代次及当前浏览根路径。
2. 解析输入形成远端候选路径，不将其插入 shell 命令。
3. 使用 SFTP `REALPATH` 获取规范路径，再用 `STAT` 查询属性，确认是目录；未知类型不乐观地当作目录。
4. 检查请求仍属于当前导航意图和有效文件连接。
5. 成功才提交新根路径，更新路径栏并显示收起的根节点。失败保留原树，输入框显示此次错误。

SFTP 的 `REALPATH`、`STAT`、`OPENDIR`、`READDIR` 和 `CLOSE` 分别支持路径规范化、属性查询和目录读取；属性查询不需要列举子项。目录属性可读不保证目录内容可列举。协议依据为 [SFTP v3 草案第 6.7、6.8、6.11 节](https://www.ietf.org/archive/id/draft-ietf-secsh-filexfer-02.txt)。

| 验证或读取结果 | 界面行为 |
| --- | --- |
| 存在且为目录 | 提交路径，等待用户展开 |
| 指向普通文件 | 提示“请输入文件夹路径” |
| 明确不存在 | 提示“目录不存在” |
| 权限不足 | 提示“无法访问该路径”，不伪装成不存在 |
| 服务端返回泛化错误 | 显示访问失败及可用原因，不推断错误类型 |
| 属性查询成功，展开时无权列举 | 在根节点或对应子节点显示读取错误 |
| 请求期间断线 | 显示文件连接错误，保留原树为不可操作的旧视图 |

验证不锁定远端目录。目录在验证后被删除、改名或修改权限时，以实际展开和传输操作的结果为准。

### 从终端选中路径

终端文本选择菜单提供“在文件树中打开选中路径”。该操作把选中的文本送入同一个路径验证流程，不执行 `pwd`，不读取终端输入状态，不自动猜测提示符或修剪路径中的合法字符。

纯粹误选、多行内容或 shell 引号包裹的文字可以在路径栏编辑后提交。按钮的语义是打开用户提供的路径，不是同步终端 pwd。终端中正在运行程序或存在未提交输入，都不妨碍这一操作。

### 导航与符号链接

展开箭头只加载子项，不改变根路径；目录的“在此浏览”操作才将它设为新根。上级按钮以当前规范根路径计算，初始目录按钮回到本次 SFTP 初始路径。刷新按钮只刷新当前根目录的下一层。

目录列表中的符号链接单独标识，不自动探测目标、递归进入或当作上传落点。用户显式打开链接时才解析并验证目标；若目标是可访问目录，作为新根打开，避免在树中自动形成循环。显式路径导航允许远端服务处理指向目录的链接。

## 目录懒加载与缓存

### 单层读取

首次展开某目录时，前端请求该目录的直接子项。SSH crate 执行目录读取，core 管理这次查询与页面意图的关联，前端合并返回的条目。

```text
展开 project            只读取 project 的直接子项
  展开 src              再读取 src 的直接子项
    components 收起     不读取 components 的内容
  assets 收起           不读取 assets 的内容
```

不为未展开目录查询是否为空、统计文件数或递归总大小。不下载内容、预览图或计算哈希。优先使用列目录响应附带的属性；缺少属性时按用户操作补查，不默认对所有条目追加属性请求。过滤导航用的 `.`、`..` 条目。

### 大目录分批读取

默认目标为每次向界面提供约 200 个条目，末尾显示“加载更多”。这是 nooboard 的呈现批次，不是远端必须返回的条目数。后端只按需要继续读取，不先收集完整目录再给前端分页。

继续读取使用后端不透明游标，关联文件连接代次、路径、目录查询 ID 和实际 SFTP 目录句柄。游标不是页码，也不承诺任意跳页。服务端一次返回的剩余条目由后端有界缓存。

同一目录同时只允许一个继续读取请求。收起时停止追加请求；已经在途的结果可以缓存，但不能强制重新展开节点。句柄在读完、错误、取消、断线或空闲超时后释放。游标失效时提示重新加载，不从不确定的偏移静默续读。

在未完整读取的目录中保留返回顺序并去重，明确显示“部分内容已加载”。不承诺全目录按名称排序或全量搜索；如提供过滤，只过滤已加载条目并明确标注范围。全部读取完成后可按目录优先、名称排序。虚拟列表只解决渲染开销，不能替代后端分批读取。

缓存使用有界容量，优先回收收起目录。达到活动目录的预算上限时停止继续读取并提示，不把截断伪装为读取完成。批次大小、并发上限和缓存预算是内部可调参数，性能验证后定值。

### 节点状态与刷新

| 状态 | 含义 |
| --- | --- |
| `Unloaded` | 知道节点是目录，但尚未读取内容 |
| `Loading` | 正在请求第一批 |
| `Partial` | 已有条目，尚未确认读取结束 |
| `Complete` | 已读完，空目录也属于此状态 |
| `Stale` | 缓存失效，下一次展开或刷新重新读取 |
| `Error` | 本节点加载失败，可以重试；已显示条目可保留并标记过期 |

前端单独维护展开和选中状态，不把“收起”等同于“尚未加载”。重新展开有效缓存不重复读取。刷新使该目录的旧查询失效，保留旧条目作为加载中视图，成功后替换。

上传完成时，如果目标目录正在展开，只失效并刷新这个目录的当前展示批次，不遍历整树；目标目录收起时只标记失效。远端其他程序产生的变化，第一版依靠用户刷新查看，不添加目录轮询或文件系统监听。

请求结果携带连接代次、导航代次及查询 ID。切换设备、重连、改根路径或刷新后，迟到结果不能污染新的视图。下载不会改变远端目录，不触发远端树刷新。

## 上传下载与目标目录

### 文件范围

已确认：第一版支持单个普通文件和多选文件上传下载，暂不递归传输整个文件夹；文件树仍支持目录浏览和懒加载。符号链接传输、特殊文件传输、原生拖出下载、断点续传和远端编辑不作为本版交付条件。

### 上传

上传按钮打开宿主原生文件选择器。按钮目标为用户明确选中的普通目录节点；未选中目录时使用当前文件树根目录。选择普通文件不会隐式变更上传目标。按钮旁显示目标路径。

本地文件拖入某个目录节点时，目标是该节点；拖入根目录空白区时，目标是当前根目录。文件节点不接受上传。悬停只高亮目标并显示路径，不自动展开或扫描目录。目录即使未展开，也可作为上传目标，但提交时仍验证其可用性。

宿主只将本地路径交给后端，文件字节不通过 React。拖拽事件必须能对应到实际目录落点；平台无法可靠提供落点时保留上传按钮，不把无法定位的拖入悄悄解释为其他目标。

### 下载

右侧面板底部提供持久化的“下载至”目录选择器，初始采用宿主可用的系统下载目录；无法取得默认值时要求先选择。此设置位于 SSH 工作区配置，与原有普通文件接收目录独立。

选中一个或多个普通文件后点击下载，所有新任务使用当时设置的目录。每项任务创建后固定目标目录；用户以后修改选择器，只影响新任务。目录不存在、不可写或已被移除时，任务明确失败，不偷偷改到其他位置。

下载完成提供“在本地文件夹中显示”。第一版不依赖 Finder、Explorer 等原生文件承诺机制实现拖出下载。

### 任务与落盘

接受任务时固定工作区、远端身份、方向、源绝对路径、目标绝对目录和重名策略。每个文件拥有独立任务 ID，多选操作可拥有分组 ID。切换目录、设备、标签或下载目录都不重新解释既有任务。

默认重名策略为保留两份，使用编号名称。第一版不默认覆盖；覆盖操作需要另行明确设计，不隐含在重试中。最终名称由后端以不覆盖方式分配和发布，不能只依赖“先检查不存在，再普通覆盖写入”。

传输先写目标目录中的唯一临时文件，完成并关闭文件后发布为最终名称。远端发布必须使用已验证的不覆盖语义；不可保证时明确失败，不能悄悄使用覆盖式扩展。不同服务器的重命名行为需要实测，不宣称所有 SFTP 服务均具备相同的原子发布保证。

取消时停止后续传输并尝试清理临时文件。清理失败保留可追踪的位置；已经发布成功的文件不能因稍后取消而误标为不存在。发布时丢失连接且无法确认结果，状态为 `Unconfirmed`，提示检查目标位置，不自动重新传输。

不为浏览或普通传输执行整目录哈希扫描。传输读取源文件时记录可取得的大小和修改信息，发现变化则提示失败；这不构成任意并发写入下的一致性快照承诺。

任务状态为 `Queued`、`Running`、`Finalizing`、`Succeeded`、`Failed`、`Cancelled` 或 `Unconfirmed`。文件连接不可用时，尚未开始的任务进入 `WaitingForConnection`。第一版提供取消和显式重试，重试从头创建新尝试，不自动断点续传。进度按实际传输字节计算，发布成功后才标记完成。

## 连接和任务生命周期

每个工作区在一次登录过程中建立两条独立的 SSH 传输连接：终端连接请求 PTY 和交互 shell；文件连接启动 SFTP 子系统。仅在同一 SSH 连接上开两个通道不满足这里的连接故障隔离要求。

| 事件 | 终端 | 文件浏览与传输 |
| --- | --- | --- |
| 切换页面或标签 | 后端会话保留 | 保留文件连接及任务 |
| 关闭文件面板 | 不变 | 停止无需求的目录读取，传输继续 |
| 正常退出 shell | 显示已结束 | 独立文件连接继续可用 |
| 终端连接意外断开 | 回到重新登录入口 | 健康的文件连接及任务继续 |
| 文件连接断开 | 健康的终端继续 | 活动任务失败或结果未确认，未开始任务等待显式重连 |
| 关闭终端标签 | 结束该终端，不暗示远端所有子进程必定退出 | 有任务时文件连接由任务持有，继续在队列展示；无需求时释放 |
| 两条连接都因网络或服务器故障断开 | 需要重新连接 | 任务不会因为进程所有权而免于网络故障 |
| 隐藏窗口且应用继续托盘运行 | 后端继续 | 后端继续 |
| 真正退出 nooboard | 停止会话 | 停止任务，等待必要清理和已经开始的发布结果 |

不因终端重连而替换健康的文件连接。文件连接重连后先使旧句柄、游标和缓存失效；旧终端输出、旧任务回调也不得归入新的连接代次。

应用重启不自动恢复远端 shell 或未完成传输。终端与 SFTP 的普通连接失败属于功能状态，不作为顶层 core runtime 的致命子任务退出，不能连带关闭剪贴板、设备发现或普通传输。

### 新增 ssh crate

新增 `crates/ssh`，包名 `nooboard-ssh`，由 core 组合。它不依赖 core、network、storage、Tauri 或 React。最小组织如下，具体文件按实现规模拆分，不预先为每个方法创建模块：

```text
crates/ssh/src/
  lib.rs                 仅通过 api 导出公开入口
  api.rs                 服务所有者、请求句柄、公开类型
  runtime/               启动、监督、停止与资源回收
  connection/            建连、主机密钥验证、认证和连接代次
  terminal/              PTY、输入输出、尺寸及退出
  sftp/                  文件连接与远端文件操作
    runtime.rs           文件连接所有权、子 runtime 装配与监督
    client.rs            SFTP 协议适配
    path.rs              远端路径解析与属性验证
    directory/           目录查询与分批读取
      model.rs           查询标识、游标、批次与读取状态
      runtime.rs         查询注册表、并发、超时、取消及回收
      reader.rs          打开目录、读取批次和关闭句柄
    transfer/            上传下载任务、进度、临时文件和发布
      model.rs           任务参数、进度与结果
      runtime.rs         任务注册表、排队、并发及取消
      upload.rs          上传执行
      download.rs        下载执行
      publish.rs         临时文件与最终发布
  credentials/           操作系统凭据库适配和秘密生命周期
```

公开模型沿用 `SshService` 不可克隆所有者、`Ssh` 可克隆句柄及明确的事件接收端。服务由 core 持有；关闭前端订阅或释放请求句柄不会关闭服务。

SSH crate 拥有真实连接、协议句柄、传输 worker 和秘密材料。core 通过公开结果和状态协调，不另建一套底层传输状态机。主机密钥确认等必须被处理的工作使用有界可靠请求通道，不能依赖可能丢失中间状态的 watch 通知。

`directory` 和 `transfer` 是 `sftp` 下并列的私有功能模块，各自拥有 `model.rs`、`runtime.rs` 和执行实现。目录查询与传输任务都有持续状态及资源回收需求，分别由各自 runtime 作为唯一状态所有者；`path.rs` 提供共享路径能力，不创建常驻 runtime。

| 状态所有者 | 职责 |
| --- | --- |
| `sftp::runtime` | 拥有文件连接，装配和监督两个子 runtime，分发连接代次变化与关闭信号 |
| `sftp::directory::runtime` | 管理目录查询注册表、实际句柄、游标、在途读取、未交付条目、并发限制和空闲回收 |
| `sftp::transfer::runtime` | 管理传输任务注册表、排队、进度、取消和发布结果 |
| core 工作区 | 管理浏览根路径、导航意图、已经交付的目录结果缓存及刷新策略 |
| 前端 | 管理节点展开、选择、输入草稿和呈现 |

每个 `SshService` 实例由 SFTP 运行时创建一套目录 runtime 和传输 runtime，通过文件会话 ID、连接代次及操作 ID 隔离工作。每次展开目录只新增查询记录及必要的受监督 I/O 任务，不创建一套新的功能 runtime 或独立线程。网络等待交给可取消、受监督的操作任务，runtime 不因等待某个目录响应而阻塞其他目录的取消或清理。

目录 runtime 只缓存当前读取中尚未交付的批次数据，已交付列表的复用缓存归 core，避免维护两套文件树缓存。目录 runtime 不管理浏览根路径和节点展开状态。目录浏览和传输任务共享文件会话的受控访问能力，不直接互相调用 runtime；上传完成由 core 决定哪些目录结果需要失效或刷新。

关闭某个目录查询只释放其句柄和读取需求，不取消文件传输。传输任务持有文件会话的使用权，不因关闭文件树而取消。文件连接断开时，SFTP 运行时按会话和连接代次通知两个子 runtime，使对应查询与任务失效，其他文件会话继续工作。普通查询或传输失败记录为操作结果，不导致整个 SFTP 服务退出。

公开的目录操作、上传下载方法及相关类型仍从 crate 的 `api` 导出，调用者不依赖内部目录层级。

### core 工作区模块

新增 `remote_workspace` 功能模块，负责设备与连接配置关联、密码记忆策略、主机信任保存、下载目录设置、导航意图、目录查询缓存及快照聚合。它持有 SSH 服务的公开句柄，不直接操作 socket、系统钥匙串或文件字节。

密码是否保存由 core 的用户策略决定，具体读写由 SSH crate 的凭据适配执行，使用不透明凭据引用。已有 network 内部凭据实现不通过暴露私有模块复用，也不把 SSH 密码混入 nooboard 设备身份材料。

storage 继续负责非秘密配置和必要公开记录，不增加 SSH 私有协议或文件传输逻辑。network 原有文件传输协议和接收流程保持独立，本功能不新增“收到文件后搬运到任意远端目录”的路径。

### Tauri 与 React

Tauri 负责原生文件及目录选择、拖拽路径与坐标适配、打开本地结果，以及 core API 与 IPC 的转换。扩展现有 `Request`、`Reply` 和订阅契约，不为每个 SSH 操作增加散落的 Tauri command。

前端在 `features/ssh` 下组织会话栏、登录表单、终端适配器、文件面板和任务队列。功能组件只使用 `desktop/api.ts`。输入草稿、展开、选择和面板宽度属于界面状态；连接、有效路径、任务结果和凭据保存结果由后端确认。

终端字节使用有序专用数据流，不将每个字符塞入全局状态快照，也不使用可能合并内容的 watch 传输。宿主复用现有订阅基础设施增加有类型的流帧。接收端进行流式解码，处理 UTF-8 和控制序列跨包；缓冲有界，断订阅后的重放缺口明确标识。

## 接口与状态契约

以下为业务接口草案，名称可按现有命名风格调整，职责与语义固定。实际协议先定义 Rust DTO，再生成 TypeScript，避免前后端手写两份结构。

| 操作 | 输入要点 | 结果与约束 |
| --- | --- | --- |
| 创建工作区 | 设备 ID、连接配置 | 返回独立工作区 ID |
| 连接或重连 | 工作区、用户名、端口、密码或凭据引用、记忆选择、连接范围 | 返回尝试 ID；终端和文件服务状态独立 |
| 确认主机密钥 | 当前尝试、挑战 ID、核验结果 | 保存成功后继续，过期挑战不能作用到新连接 |
| 输入终端 | 终端 ID、连接代次、字节 | 仅送到对应交互通道 |
| 调整终端尺寸 | 终端 ID、行列数 | 只改变 PTY 尺寸 |
| 关闭终端 | 终端 ID | 不取消文件任务 |
| 导航目录 | 工作区、文件连接代次、原根路径版本、输入文本 | 验证后返回规范根路径；过期导航被拒绝或忽略 |
| 读取目录 | 工作区、目录标识、查询 ID、可选游标 | 返回条目、读取是否结束、下一游标及查询版本 |
| 停止目录读取 | 查询 ID | 停止后续批次，释放或限时保留句柄 |
| 刷新目录 | 工作区、目录标识 | 失效旧查询，重新读取当前需求批次 |
| 提交上传 | 工作区、本地源文件、明确远端目标目录 | 返回任务 ID；后端固定参数 |
| 提交下载 | 工作区、远端条目标识 | 后端读取当前下载目录并固定到任务 |
| 更改下载目录 | 宿主选择的本地目录 | 保存到 SSH 独立设置，只影响新任务 |
| 取消或重试 | 任务 ID | 由后端返回实际结果，不由前端推测成功 |

工作区快照至少包含设备与连接配置摘要、实际地址、终端状态、文件连接状态、有效浏览根路径和关联任务 ID。密码不进入快照。目录条目通过功能查询返回，不把整棵文件树持续广播到全局快照。

目录条目包含稳定于本次查询的 ID、展示名称、远端路径标识、类型及可选大小、修改时间和权限。真实远端路径保存在后端，操作不从显示名称重新猜测路径。未知属性保持未知，不显示为零或据此断言可访问。

所有请求按作用域携带工作区、连接和查询身份。IPC 中后端 ID 与大整数遵循现有字符串编码规则；终端帧另有序号用于排序与缺口检测。错误采用稳定代码，展示层本地化，底层诊断不得夹带密码或终端正文。

## 实现顺序

1. 定义 SSH 服务公共接口、生命周期、远端路径类型和错误契约。用最小程序验证密码认证、主机密钥核验、PTY、真正分批的目录读取以及单文件上传下载，选定 Rust 库。
2. 接入 core 工作区与配置，验证两条连接独立、凭据策略、失败回表单和任务所有权。完成普通文件双向传输及临时文件发布，再接复杂界面。
3. 扩展 Rust IPC DTO、生成协议和前端公共 API，同时补齐 preview 场景。完成一个设备的登录、终端、路径输入、展开一层和上传下载闭环。
4. 完成顶部多会话、右侧面板、分批加载、缓存与刷新、下载目录选择及终端选中路径定位。
5. 接入原生拖入上传、后台任务队列、关闭标签后的任务展示，以及 macOS、Windows、Linux 实机兼容验证。

终端渲染组件和 Rust 依赖可以在稳定契约后替换。产品行为和模块职责不因为依赖选择而反复改变，也不为未来递归传输提前抽象通用传输框架。

## 验收条件

| 场景 | 必须观察到的结果 |
| --- | --- |
| Bash、Zsh、fish、PowerShell 或未知 shell | 文件浏览和传输不需要 shell 专用脚本；启动过程不改 shell 配置 |
| 远端正在运行 Vim 或输入了半条命令 | 路径导航及选中文本定位不向终端写入查询命令 |
| 初次连接文件服务 | 只验证初始目录，不调用目录枚举 |
| 输入路径但未提交 | 不产生远端查询 |
| 有效目录路径 | 属性确认后切换根节点，保持收起 |
| 不存在、普通文件或权限不足 | 显示对应错误，原有效根目录不变 |
| 无权列举但可查询属性的目录 | 导航可成功，展开时显示节点错误，终端仍工作 |
| 只展开一层 | 只读取该目录的直接子项，不读取未展开目录 |
| 超大目录 | 第一批可显示，后续读取由加载更多触发，后端未提前枚举全部 |
| 快速输入两个不同路径 | 旧请求迟到不覆盖新导航结果 |
| 切换标签、设备或重连 | 旧字节帧、缓存、目录游标和回调不进入新连接 |
| 收起再展开 | 有效缓存可复用；未完成查询按有效游标继续或明确要求重载 |
| 上传到未展开目录 | 可提交，未自动遍历；完成后缓存失效 |
| 更改下载目录或文件树根路径 | 已提交任务的目标目录保持不变 |
| 同名文件与并发任务 | 保留两份，不覆盖原文件，不互相争抢临时文件 |
| 终端断开或关闭标签 | 健康 SFTP 连接上的任务继续并可查看 |
| SFTP 连接断开 | 终端可继续，任务如实失败、等待连接或结果未确认 |
| 发布期间断线或取消 | 不把已经发布或结果不明的文件误标为确定未保存 |
| 密码记忆未勾选 | 成功连接可用，后续重新认证需要输入；配置和日志无密码 |
| 密码记忆勾选 | 认证成功后才保存；保存失败不伪装成功 |
| 连接失败 | 表单密码清空，记忆勾选清除，原凭据不再一键使用 |
| IP 改变但设备和主机身份相同 | 新连接解析新地址并执行主机密钥检查 |
| SSH 主机密钥不匹配 | 认证前停止，不因 nooboard 已配对或重新输入密码而放行 |

测试分为 SSH crate 的协议与生命周期测试、core 的策略及过期结果测试、前端交互与 IPC 契约测试，以及跨平台实机验收。目录懒加载必须通过请求计数验证，独立连接必须通过单独断开其中一条连接验证，不能只检查界面状态。

实现涉及 IPC 后执行 `npm run ipc:generate`，并通过 `ipc:check`、`architecture:check`、前端测试与生产构建。Rust 按仓库要求执行格式、架构、测试和 clippy 检查。当前文档定稿不代表这些功能或跨平台行为已经实现、测试通过。
