# SSH 工作区设计

本文记录当前 SSH 工作区的实现契约，面向维护者。用户操作见 [SSH 使用指南](ssh-guide.md)，crate 公共接口见 [nooboard-ssh](../crates/ssh/README.md)，测试与尚待实机验证的范围见 [测试文档](testing.md)。

## 功能边界

- 选择已配对设备，以系统账号和密码连接对方已有的 SSH 服务。
- 终端和 SFTP 使用独立 SSH 连接，可分别失败、关闭及重连。
- 顶部管理会话，主区域显示终端，右侧目录树按需展开，底部显示跨会话文件任务。
- 文件浏览由 SFTP 完成，不使用 shell 钩子、`pwd` 轮询、提示符解析或命令注入。
- 上传和下载均属于 SSH/SFTP 服务，普通 nooboard 文件传输继续由 network 管理。
- 只传输普通文件，支持多选；不实现递归目录传输、断点续传、跨进程任务恢复或原生拖出下载。

## 模块与所有权

```text
React features/ssh
  → desktop/api → desktop runtime → Tauri IPC
  → core::Remote
  → nooboard-ssh
      connection/                握手、认证、主机密钥决策
      terminal/                  PTY、输入、尺寸、输出与回放
      sftp/
        runtime.rs               文件连接与服务装配
        path.rs                  远端路径解析及目录属性验证
        directory/
          model.rs               条目、批次和游标
          runtime.rs             查询注册、取消、期限和回收
          reader.rs              按需 READDIR
        transfer/
          model.rs               固定任务与结果
          runtime.rs             排队、并发、取消与重试
          upload.rs              上传普通文件
          download.rs            下载普通文件
          publish.rs             临时文件发布与重名处理
      credentials/               秘密包装和系统凭据适配
```

`AppService` 拥有 SSH 服务，页面与 WebView 订阅不拥有它。每个服务实例只有一套 directory runtime 和 transfer runtime；展开目录新增查询记录及受监督 I/O 任务，不为每个节点新建服务。

core `remote` 负责配对设备查找、地址解析、登录配置、凭据保存策略、主机信任、浏览根路径与已交付目录缓存。SSH crate 只缓存正在读取但尚未交付的条目。目录与传输共享文件连接的访问能力，不直接互相调用 runtime。

Tauri 负责原生文件/目录选择、拖入坐标转换和在文件管理器中显示结果；业务通过 core 的公开句柄访问。前端只管理标签选择、表单草稿、树展开和文件勾选。

## 地址与连接身份

登录配置绑定稳定设备 ID、用户名与 SSH 端口。每次连接读取最新发现地址、显式配置的主机地址和已保存候选地址。发现服务提供的地址包含配对端口，接入层保留 IP 与 IPv6 scope，并替换为用户选择的 SSH 端口。

IP 变化不会改变设备标识，也不会让已有 SSH 连接自动迁移；下一次连接重新解析候选。nooboard 在线状态与 SSH 服务可达性分别处理，已有 SSH 会话不会仅因发现记录离线而被强制终止。

逻辑工作区 ID 与实际终端、文件连接 ID 分离。只重连失败的一侧，健康连接保留。改变用户名或端口会建立新工作区，已有任务继续绑定原账号、服务和设备。

## 主机信任与密码

nooboard 配对证书与 SSH 主机密钥是独立信任材料。两条 SSH 连接均在认证前检查主机密钥。

1. 未保存主机密钥时，SSH 服务发出可靠的指纹挑战。
2. 用户确认后，core 先持久化公开主机密钥，再回复允许认证。
3. 保存失败或用户拒绝时，不继续提交密码。
4. 已知主机密钥不匹配时停止连接，必须经独立的移除信任操作后重新核验。

信任记录按设备与 SSH 端口保存，不仅按可变 IP 保存。发现地址不构成信任授权。

密码不序列化到状态或日志。一次密码输入可以短暂保留在后端，供本次两条连接认证使用。记住密码需要显式勾选且认证成功；实际存储使用操作系统凭据库，配置只保存不透明引用。

发起尝试前，core 持久化清除已保存凭据的一键使用资格。成功后按用户选择保存并恢复资格；失败时保持禁用并尝试删除旧凭据，删除失败也不能继续自动使用。失败表单清空密码及记忆勾选，保留账号与端口。保存凭据失败不撤销已成功连接，但必须报告未保存。

用户关闭会话、正常退出 shell、无效路径和单个文件失败不等同于认证失败。终端与文件连接的失败分别跟踪，另一侧后来失败时也必须重新执行凭据策略。

## 路径验证与导航

连接 SFTP 后，仅验证初始目录，不枚举目录内容。输入路径后按 Enter 或点击「打开路径」才查询；输入期间不逐字符发送请求。

导航使用 `RemoteFileTarget { workspace, files, generation }` 固定工作区、文件连接和已提交根路径版本。core 另维护本次导航意图序号，以拒绝迟到结果；失败导航不会改变已提交的根版本。

```text
输入路径
  → RemotePath 解析候选
  → SFTP REALPATH
  → SFTP STAT，确认目录属性
  → 再次核对连接与导航意图
  → 更新根路径，清空旧查询与缓存，显示收起的根节点
```

绝对路径交给远端服务；相对路径以文件树根目录为基准。`.`、`..` 由远端路径规则解析。`~`、`$HOME` 和 `%USERPROFILE%` 不作 shell 展开。Windows 盘符绝对路径转换为斜杠形式；最终命名空间由远端 SFTP 服务决定，不能按本机 `PathBuf` 解释远端路径。

不存在、非目录、权限不足及通用服务端错误分别反馈。验证失败保留原根路径；属性可读不保证可列举，后续展开仍可能失败。验证并不锁定远端目录。

「打开终端选中路径」使用相同验证流程，当前界面接受非空、单行选区并修剪两端空白；需要保留边界空格的路径应在路径栏输入。它不是终端目录同步功能，不检测 shell 是否空闲。

当前导航入口是路径栏、初始目录按钮及终端选区按钮；上一级可输入 `..`。点击普通目录行展开/收起并选择上传目标，不会改变浏览根路径。符号链接单独显示，只有显式点击时才验证目标；不自动跟随或作为上传落点。

## 目录读取、缓存与过期结果

展开目录时只请求直接子项。尚未展开的子目录不会被探测是否为空、计数或扫描总大小，也不下载内容或预览图。

SSH 使用底层 `OPENDIR` / `READDIR` / `CLOSE` 和不透明游标按需读取，不先完整 `read_dir` 再切前端分页。默认一次交付约 200 项；服务端返回的一批中未交付部分由 reader 有界保留，继续读取由「加载更多」触发。过滤导航条目 `.` 和 `..`。

core 缓存已交付条目，状态包括 `Loading`、`Partial`、`Complete`、`Stale` 和 `Error`。没有缓存记录表示未查询，展开/勾选状态单独由前端管理。完整缓存可重用；收起会取消未完成查询，不保证旧游标永久有效。

切换根目录、重连或刷新会使相关查询失效。回包需要匹配连接、根版本与查询代次，才能更新缓存。每工作区最多缓存 128 个已查询目录、约 20,000 个已交付条目。

上传成功后，core 标记对应目录缓存失效；前端只刷新仍展开的目录。远端其他程序造成的变化由用户刷新查看，不轮询整个目录树。目录缓存为不可变共享快照，传输进度更新不复制或重复发送未变化的列表。

## 文件任务与发布

上传按钮打开原生多选文件对话框；目标为最近选中的目录，未选择时使用根目录。拖入目录行使用该目录，拖入树空白使用根目录，文件行拒绝作为目标。悬停不触发目录展开。

下载在提交时读取 SSH 下载目录，并固定到每个任务。改变下载目录、根路径或当前标签不会改写已提交参数。任务的原账号、端口、设备与绝对源/目标在重试时保留。

传输写入目标目录下的临时文件，完成后以不覆盖方式发布；重名选择新名称。下载使用同目录排他硬链接发布，不支持硬链接的文件系统明确失败；上传使用 SFTP v3 的不覆盖 RENAME，不调用覆盖式 POSIX rename。

| 状态                              | 含义                                                 |
| --------------------------------- | ---------------------------------------------------- |
| `Queued` / `WaitingForConnection` | 等待执行或可用文件连接                               |
| `Running`                         | 正在传输                                             |
| `Finalizing`                      | 正在完成保存与发布                                   |
| `Succeeded`                       | 已确定保存成功                                       |
| `Failed` / `Cancelled`            | 确定失败或取消，可显式从头重试                       |
| `Unconfirmed`                     | 发布结果不确定，保留目标与临时路径供核查，不直接重试 |

取消是协作式的。已经发出的文件操作需要取得结果，已开始的发布不能因取消而被错误报告成文件未保存。任务持有连接租约，关闭标签时仍有排队或运行任务的 SFTP 连接被保留。

## 生命周期

| 操作或故障           | 终端                   | 文件任务                             |
| -------------------- | ---------------------- | ------------------------------------ |
| 切换页面或标签       | 连接继续，输出有界回放 | 继续                                 |
| 关闭标签或退出 shell | 终端关闭或结束         | 健康 SFTP 上的任务继续               |
| 终端连接失败         | 可重新登录             | 健康 SFTP 保留                       |
| 文件连接失败         | 健康终端保留           | 按实际阶段失败、等待连接或结果未确认 |
| 完全退出应用         | 停止                   | 受控关闭并等待必要清理               |

没有待处理任务的已关闭工作区会回收文件连接。工作区和回放记录受容量限制；不承诺终端全文或文件任务跨进程恢复。

## IPC 与终端输出

`RemoteRequest` / `RemoteReply` 使用既有 `request` 命令。`Remote` 状态、`Terminal` 字节与 `TerminalReset` 是独立帧类型，不把终端正文塞进全局业务快照。

输入、尺寸与回放必须同时携带工作区和实际终端连接 ID；文件操作携带 `RemoteFileTarget`。过期页面回调不能作用到重新认证后的新连接。ID 与偏移等大整数经 IPC 用字符串表示。

xterm.js 只处理终端渲染和输入。订阅先于回放，前端按字节偏移去重并恢复缺口；默认每终端保留最近 1 MiB 输出。超过缓冲区会明确提示缺口，不拼接成完整历史。输入串行提交并按 16 KiB 分块，尺寸随容器变化更新 PTY。

WebView 隐藏时不持续发送输出帧，恢复或订阅落后时触发回放。状态更新可以合并；未变化的目录列表在 IPC 中省略，由前端仅在相同工作区、文件连接下复用。完整边界见 [桌面架构](../apps/desktop/ARCHITECTURE.md)。
